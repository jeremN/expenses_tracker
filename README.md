# Expenses Tracker

A personal finance app for tracking income, expenses, recurring payments, and investments. Built to run on Cloudflare's free tier.

This is a rewrite of an earlier version (React 16 / Redux / Firebase) using a modern stack.

## What it does

- Record income and expenses, assign them to categories
- Set up recurring rules (weekly, monthly, yearly) that auto-generate transactions
- Import bank statements from CSV files (auto-detects columns, handles European number formats)
- Track investment portfolio value over time with snapshots
- View monthly trends and category breakdowns
- Dark mode

## Stack

| Layer | Tech |
|-------|------|
| Framework | [TanStack Start](https://tanstack.com/start) (React, SSR, file-based routing) |
| Database | [Cloudflare D1](https://developers.cloudflare.com/d1/) (SQLite at the edge) via [Drizzle ORM](https://orm.drizzle.team/) |
| Auth | [Cloudflare Zero Trust](https://developers.cloudflare.com/cloudflare-one/) (no app-level auth code) |
| UI | [shadcn/ui](https://ui.shadcn.com/) + [Tailwind CSS v4](https://tailwindcss.com/) |
| Validation | [Zod](https://zod.dev/) (shared between client and server) |
| Monorepo | [Turborepo](https://turbo.build/) + [pnpm workspaces](https://pnpm.io/workspaces) |

## Project structure

```
apps/
  web/              TanStack Start app (pages + API routes)
packages/
  db/               Drizzle schema and query functions
  shared/           Zod validators and TypeScript types
```

The query layer in `packages/db` is not coupled to D1 specifically — it uses Drizzle's `BaseSQLiteDatabase` type, so it can work with any SQLite backend (better-sqlite3, libSQL, etc.). This was done on purpose: the monorepo setup exists because I might experiment with desktop or mobile clients in other languages later. The REST API at `/api/*` is there for that reason too.

## Getting started

Prerequisites: [Node.js](https://nodejs.org/) 18+, [pnpm](https://pnpm.io/) 9+.

```bash
pnpm install
```

### Local development

```bash
pnpm dev
```

This starts the Vite dev server with the Cloudflare Workers runtime.

### Database setup

Create a D1 database and update `apps/web/wrangler.jsonc` with your database ID:

```bash
npx wrangler d1 create expenses-tracker-db
```

Then generate and apply migrations:

```bash
cd packages/db
pnpm db:generate
npx wrangler d1 migrations apply expenses-tracker-db --local   # local dev
npx wrangler d1 migrations apply expenses-tracker-db --remote  # production
```

### Deploy

```bash
cd apps/web
pnpm deploy
```

This builds the app and deploys it to Cloudflare Workers. You'll need a Cloudflare account and `wrangler` authenticated.

### Tests

```bash
pnpm test
```

Tests cover the CSV parser (delimiter detection, date/number format handling, column auto-detection) and utility functions.

## Data model

Five tables: `categories`, `transactions`, `recurring_rules`, `investment_snapshots`, `bank_imports`. All monetary amounts are stored as integers (cents). Dates are `YYYY-MM-DD` strings. See `packages/db/src/schema.ts` for the full schema.

Recurring transactions are not generated by a cron job. Instead, missing transactions are created on dashboard load — the Cloudflare Workers free tier doesn't include scheduled workers, and this keeps things simple.

## API

The app serves both SSR pages (via TanStack Start server functions) and a REST API at `/api/*`. Both share the same query layer from `@tracker/db`. The REST endpoints exist for potential future use by non-web clients.

| Endpoint | Methods |
|----------|---------|
| `/api/transactions` | GET, POST |
| `/api/transactions/:id` | GET, PUT, DELETE |
| `/api/categories` | GET, POST |
| `/api/categories/:id` | GET, PUT, DELETE |
| `/api/recurring` | GET, POST |
| `/api/recurring/:id` | GET, PUT, DELETE |
| `/api/investments` | GET, POST |
| `/api/investments/:id` | DELETE |
| `/api/import` | POST |
| `/api/stats/monthly-summary` | GET |
| `/api/stats/category-breakdown` | GET |
